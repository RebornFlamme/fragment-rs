## 3. Choix de découpage
1. **Un socle léger** (`fr-t6-socle`, le chef ou un équipier en moins de 15 minutes) : dépendance de chemin de
   `fragment-ui` vers `fragment-artefacts`, coquilles `fragment-ui/src/artefacts/{mod,service,cache_disque,
   reconciliateur,suivi_ancre,menu,masques,placement,objet_html,montage}.rs`, `fragment-ui/src/doc_widget/pin.rs`,
   les lignes `mod`. Ensuite, chaque tâche ne touche que ses fichiers.
2. **Le journal dans l'app en Opus** (`fr-t6-service`) : c'est l'invariant de Fragment (§19.1 de son journal :
   seul `dispatch` change l'index, un segment = un écrivain, objet avant la ligne, rien de détruit sans intention).
   L'hôte (`fragment-ui/src/artefacts/service.rs`) relie le coffre (événements avec origine), le tic (`poll`),
   la perte de focus et la fermeture (flush) au manager déjà porté ; `fragment-app` ne fait que lui donner ses
   chemins. Le dossier de données de l'utilisateur (`device.json`, journal local, cache) est décidé ici.
3. **Les autres écrivains et le cache à part** (`fr-t6-autres-ecrivains`) : événements BRUTS de
   `.fragment/artefacts/journal/**` (ajout minimal dans `surveillance.rs`, qui ignore aujourd'hui tout chemin
   caché), lecture incrémentale par curseur, cache d'index sur disque JETABLE (remplace IndexedDB : « 0 ligne lue »).
4. **Le réconciliateur en Opus** (`fr-t6-reconciliateur`) : la passe record → widget sur le `WidgetLayer` de T5,
   l'`AnchorTracker` (suivi écrit en fin de geste, orphelins), le registre des kinds. Testé sur la fausse surface de
   T5 ; branché sur les vraies vues par `fr-t6-montage`.
5. **DocWidget persistant** (`fr-t6-pin`) puis **repli** (`fr-t6-repli`) : le service en mémoire de T5 devient
   le service persistant (même contrat), la bascule `open` est écrite au pin. Le repli touche le cadre de T5.
6. **HTML et commandes séparés** : `fr-t6-placement` (commandes externes, pures autour de `find_passage`) et
   `fr-t6-objet-html` (le rendu). Le rendu d'un objet passe par le traducteur natif d'ADR-012 ; ses `<script>`
   attendent une décision (§7.1).
7. **Dépendances vers T5** (posées sur les tâches) : `fr-t6-montage` → `fr-t5-montage-note`, `fr-t5-montage-pdf` ;
   `fr-t6-livraison` → `fr-t5-livraison` (fichiers `pixels/tranches.json`, `pixels/cliquet.json`). Vers T7 :
   `fr-t7-montage` → `fr-t6-service` (les sessions de l'agent vivent dans le manager de l'app ; un seul manager
   par coffre).

## 7. Risques
1. **Scripts des objets HTML** : Fragment exécute leurs `<script>` dans le renderer (`new Function`, Shadow DOM,
   `requestAnimationFrame`, `<canvas>`). fragment-rs n'a ni DOM ni JS en T6 : le traducteur natif (ADR-012) rend le
   HTML et le CSS confiné, pas un script. Options : (a) T6 sans scripts (message dans l'objet, tests 2 et 4 en
   partie n.a.) et scripts au runtime JS de T10 (S3) ; (b) une WebView possédée par objet (S2) dès T6, au prix de
   l'invisibilité au harnais pixels (ADR-012 §5) ; (c) un mini-DOM pour scripts. Recommandation : (a). À trancher
   par l'orchestrateur avant `fr-t6-objet-html`.
2. **Dossier de données de l'utilisateur** : n'existe pas encore dans fragment-rs (`device.json`, journal local,
   cache). Un mauvais choix fusionne deux appareils (même `deviceId` copié) ou perd les records locaux. Proposé :
   `%APPDATA%/fragment-rs/` (pas celui de Fragment, pour ne pas écrire dans ses segments) ; à confirmer.
3. **Coexistence avec Fragment sur un même coffre** : les deux écrivent `.fragment/artefacts/journal/` ; le pli
   commute, mais un kind inconnu d'un côté doit rester inerte, jamais réécrit. Test dédié dans `fr-t6-service`.
4. **Surveillance de `.fragment/`** : `surveillance.rs` ignore tout chemin caché ; l'exception doit rester
   étroite (journal seulement), sinon chaque écriture de config relance l'explorateur.
5. **Fin de geste** : le pin s'écrit à la fin d'un geste (`ctx.self.set`), jamais par `pointermove` ; l'ordre des
   événements de GPUI n'est pas celui du DOM (même risque que T5 §7.5).
6. **Ordre des livraisons** : `pixels/tranches.json` et `cliquet.json` sont tenus par T5, T6 et T7 ; le chef
   fusionne les livraisons l'une après l'autre (T7 n'a pas de dépendance posée vers T6 pour ces fichiers).
