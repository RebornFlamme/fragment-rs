## 3. Choix de découpage (tranchés sans question, à relire par le chef)
1. **Les dépendances de blocage vont sur les TÂCHES, pas sur l'épic.** Constaté le 11/11 : Beads propage le
   blocage d'une épic à TOUS ses enfants (`bd blocked` : « Blocked by fr-t2 »). `bd dep add fr-t2 fr-t1.3`
   aurait gelé les modèles purs de T2. fr-t1.3 (largeur du texte, à fermer avant le RENDU de T2) est donc posée
   sur `fr-t2-tree-item`, première tâche de rendu, dont dépend tout le rendu aval.
2. **`fr-p3-socle` d'abord** (commune à T2, T3, T4, T11) : coquilles de modules dans `fragment-ui`,
   `fragment-markdown`, `fragment-pdf`, dépendances de chemin, et `cargo xtask parite` qui lit
   `crates/<crate>/parite.d/*.toml`. Ensuite AUCUNE tâche ne partage `lib.rs`, `scene.rs` ni `parite.toml`
   (modèle : `fr-t1-squelette`). Modules de T2 posés : `tree_item`, `explorateur`, `coffres`, `lecture`,
   `vue_fichier`. Le socle ne touche ni `fragment-core`, ni `fragment-theme`, ni `fragment-cli`.
3. **Le Vault vit dans `fragment-core/src/vault/`** (contrats). `fr-t2-vault` pose les coquilles de ses aval
   (`fs.rs`, `surveillance.rs`, `metadonnees.rs`) ; `fr-t2-fs` et `fr-t3-metadata` les remplissent ensuite en
   parallèle. ★ Seul chevauchement de fichier du plan : UNE ligne `pub mod vault;` dans `fragment-core/src/lib.rs`,
   possédé par `fr-t1-reglages` (en cours). Rebase juste avant la PR ; le chef peut aussi attendre la fusion de
   réglages.
4. **API du coffre SYNCHRONE**, comme `fragment-artefacts::fs` : pas d'`async` dans le cœur ; la surveillance
   tourne dans un fil et pousse des événements.
5. **L'écrivain du registre des coffres va dans `fragment-cli`** (`coffres.rs`), à côté de son lecteur : un seul
   format, un test croisé.
6. **Modèle, composant, montage** : les modèles (cœur, cli) et les composants (`tree_item`, `explorateur`) sont
   testés seuls et ne dépendent pas de `fr-t1-binaire` ; seul le MONTAGE (`fr-t2-montage`, puis gestionnaire et
   lecture) en dépend.
7. **Scènes écrites à part, par une tâche locale** (`fr-t2-scenes`) : spec.ts, JSON et références sur le portable,
   dès maintenant. Le JSON n'emploie que le schéma actuel du lecteur (une action inconnue est une erreur de CI) ;
   les scènes du gestionnaire (autre fenêtre) n'ont que leur spec et leur référence : leur JSON vient avec
   `fr-t2-gestionnaire`, qui étend le lecteur. Une tâche aval peut modifier ces JSON une fois `fr-t2-scenes` fermée.
8. **Coffres de fixture par tranche** (`pixels/vault-t2/`, puis `vault-t3`…) : ajouter des fichiers à `pixels/vault/`
   changerait l'explorateur des 22 références historiques.
9. **`fr-t2-tranches`** remplace `TRANCHE_COURANTE` (un ordinal) par `pixels/tranches.json` (une liste) : T2, T3
   et T4 finissent dans n'importe quel ordre. Elle attend `fr-t1.1`, propriétaire de `xtask/src/pixels*`.

## 7. Risques
1. **Écho de la surveillance** : l'app écrit, `notify` renvoie l'événement ; sans garde, double événement
   (origine fausse, re-rendu, cascade d'artefacts). Test obligatoire dans `fr-t2-fs`.
2. **`notify` diffère entre Windows et Linux** (renommages en deux temps, rafales) : tests sur les deux runners.
3. **Corbeille système** : pas de dépendance autorisée d'avance (`trash`) ; repli API Windows via `windows`
   (autorisée). À noter dans la PR.
4. **Boîte native de choix de dossier** (gestionnaire) : `rfd` n'est pas autorisée d'avance ; à noter.
5. **Reprise de la position « jusqu'à stabilité »** : GPUI ne jette pas le défilement d'une vue cachée comme
   Chromium (l'étage 2 peut être presque vide) ; le test reste, il prouve le comportement, pas le mécanisme.
6. **Largeur du texte** (fr-t1.3) : tant qu'elle n'est pas close, aucun rendu de T2 ne démarre (dépendance posée).
7. **Chevauchement d'une ligne** dans `fragment-core/src/lib.rs` avec `fr-t1-reglages` (§3.3).
