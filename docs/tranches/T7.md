## 7. Risques
1. **Harness sans SDK** (§2, ★) : le protocole de contrôle du binaire (permissions par l'entrée standard, hooks,
   interruption) n'est pas une API publique stable ; S8 le vérifie contre la version installée et épingle la
   version minimale (`engine_model`). Repli : processus Node du SDK, ADR et orchestrateur.
2. **Contenus de Fragment** : `prompt.md` (le prompt de l'agent) et les skills pédagogiques (verbatim d'un tiers)
   vivent dans le dépôt PRIVÉ ; les embarquer serait une copie (ADR-007). À trancher : réécrire le prompt, lire
   les fichiers d'une installation de Fragment, ou livrer sans skills.
3. **Moteur d'orbes** (MIT, tiers) : Fragment l'a recopié depuis ses sources ; le port Rust traduit la bibliothèque
   d'origine (licence MIT citée), pas la copie de Fragment. À confirmer par l'orchestrateur.
4. **Un éditeur en lecture seule par part** : coût mémoire et layout sur une longue conversation (perf de
   Fragment : 40 conversations en marge) ; la mise à jour par delta pendant le flux est exigée, jamais une
   reconstruction.
5. **Défilement sans saut** : l'ancre de lecture `{message, dy}` rejouée autour des reconstructions et la réserve
   `.chat-tail` dépendent du moment où GPUI donne les hauteurs ; une image de retard se voit dans `chat-scroll`.
6. **Coût réel** : le spike consomme le compte Claude de l'utilisateur (quelques tours) ; aucun test de CI ne lance
   le vrai `claude`.
7. **Pixels d'un fil** : les messages passent par le rendu de la note ; toute dette de T3 (glyphes, maths) se
   retrouve dans `t7-chat-markdown`.
