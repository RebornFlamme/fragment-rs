## 7. Risques
1. **DocWidget en T5 ou en T6** (§3.3) : divergence avec program.md §5 → à confirmer par l'orchestrateur ; sans
   elle, trois specs de T5 sont intestables.
2. **Positionner au-dessus de l'éditeur GPUI** : un `div` absolu par-dessus un `Element` qui défile ; la passe
   « lire toutes les ancres, puis écrire » doit tenir dans UNE image (`coords_at_pos` après le layout de
   l'éditeur, `on_after_layout` / `prepaint`). Si GPUI n'offre pas ce point, ADR et bead « fork ».
3. **Surlignage SOUS le texte** : le fork de `gpui-base` peint le texte ; dessiner sous lui sans `Decoration.mark`
   demande un crochet de peinture avant les glyphes. Absent → extension du fork n°1 (bead « fork », compté).
4. **Racine de marge non zoomée** sur le PDF : défile avec le plan, annule son zoom ; les tailles y sont en px
   écran (gutterBand, écart 8, seuils). Tout écart se voit dans `t5-mode-marge-pdf`.
5. **Activation après le geste** (pointerup puis un tour) : un widget qui bouge entre appui et relâché perd le clic ;
   l'ordre des événements de GPUI n'est pas celui du DOM.
6. **Visibilité cachée mais mesurée** (`visibility: hidden` des membres d'une grappe) : en GPUI, un élément non
   peint doit garder sa mesure, sinon l'arbitre oscille.
7. **Transitions** (marge 90 ms, aller = retour sans saut) : vérifiées par échantillons d'images en headless ;
   les scènes figent l'état final (animations coupées).
